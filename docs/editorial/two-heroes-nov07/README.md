# Mobile badges and two approved hero replacements

Scope: compact mobile category badges and the Peter/Margaret and history-of-gold hero images. Existing article content, dates, titles, SEO descriptions, routes, canonical/hreflang mappings and references remain unchanged in all four languages.

The two supplied 1280 by 720 JPEG originals are copied byte-for-byte under descriptive new public article paths. The manifest records native dimensions, file sizes, hashes, source filenames and supplied metadata. No image generation, cropping, stretching or upscaling is used in asset preparation. Existing responsive WebP delivery remains in use. The originals are explicitly used for Open Graph/Twitter and Article ImageObject metadata, including native dimensions and MIME type. Original and rendered responsive URLs are associated with the article in its image sitemap.

The images are credited as editorial images supplied for PRESDA. Photographer, date, archival provenance and reuse licenses were not supplied; none are invented. The Peter image is not identified as an authenticated historical photograph. Localized image captions explain the available credit/provenance without changing the article body.

Both records opt into the existing preserve-aspect hero option. The shared component now makes that explicit option eligible for the existing full-image composition, rather than requiring membership in a past editorial batch. Existing eligible heroes retain their classes and geometry. Full source width and height fit naturally, while the existing viewport-aware text fitting keeps desktop titles, subtitles, category/date and reading time visible.

CategoryBadge retains its design-system defaults on desktop. Responsive CSS custom properties explicitly set mobile badges below 768 px to 10 px text, 14 px line height, 4 px vertical/8 px horizontal padding and 4 px radius. Arabic's previous 1.8 line-height fallback is retained on desktop and replaced with the shared 14 px mobile value. Existing bold white text, red background, logical inset placement and larger parent link hit targets remain unchanged. Featured, supporting, Latest carousel and ArticleCard contexts all use this component.

Visual review identified face overlap in the upper corners of compact supporting thumbnails. Mobile supporting and Latest thumbnails therefore place the compact badge in the lower logical-start corner, retaining the 8 px inset. Larger featured and ArticleCard image corners keep their existing placement. No image, card size or desktop placement changes are needed for this adjustment.

Validation artifacts are retained in workspace outputs and test-results: semantic preservation across 411 articles and 1,233 translation records, 20 desktop badge baseline cases, mobile/desktop badge regressions, two-hero regressions across four languages and seven local viewports, original-image hash/MIME checks, server-rendered preview/schema checks, public crawl rules and image sitemap associations. Production release proof is recorded after Vercel READY, live tests and visual comparison with Bruno.

Pre-release results: final build generated 1,712 pages; 56 hero cases and 60 badge cases passed locally. The final badge run explicitly verified lower-corner placement on compact thumbnails and matched all 20 desktop baseline cases. All 1,644 preview editions passed, including preservation of the 1,636 unrelated edition baselines. Image policy decoded 470 sources and 2,067 delivery files. All seven previously enabled preserve-aspect heroes retained their prior class eligibility. Both new originals and all eight localized hero compositions were visually reviewed against Bruno. Live release gates are 16 hero cases, 60 badge cases, 24 raw crawler pages, six original-image crawler fetches, four responsive WebP responses and availability of both old original image URLs.
